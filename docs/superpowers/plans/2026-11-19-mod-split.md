# editor と Files 連携を独立した mod にする 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** layout を廃止し、editor（＋ファイル検索のオーバーレイ）と Files 連携を、herdr.dev/mods に載る2つの独立した公開物にする。

**Architecture:** 開く処理を Files のフォークから `src/ui/opener.ts` に移し、新しいオーバーレイ mod と Files のフォークの両方がビルド時に取り込む。editor は `props.key` なしでも開けるようにする。ビルドは mod を公開物のフォルダ（`editor/`、`files/`）に出力し、layout、アンインストール用の mod、install/uninstall スクリプトは削除する。

**Tech Stack:** TypeScript / JavaScript（gpui-kit の mod）、Bun（ビルドとテスト）、oxlint、oxfmt、dependency-cruiser。Herdr Desktop 0.1.16（macOS）。

**Spec:** `docs/superpowers/specs/2026-11-19-mod-split-design.md`（#29）

## Global Constraints

- mod のフォルダ名は変えない: `herdr-app-editor`、`herdr-app-editor-files`。新しいオーバーレイは `herdr-app-editor-open`。名前はすべて `src/core/names.ts` から使う。
- 下書きと pane の状態の保存先は変えない: `appHome()/data/herdr-app-editor/`。
- mods に載せるフォルダに `layouts/` を置かない。1フォルダ＝1公開物＝1 `RECIPE.md`。リポジトリのルートに `RECIPE.md` を置かない。
- キーの既定は `cmd-o` → `mod.open:herdr-app-editor-open`（`editor/keys.json` の `global`）。
- 依存のルール（`.dependency-cruiser.cjs`）を守る。`src/core/` は host を import しない。entries 以外は entries を import しない。
- Files のフォークの先頭コメント（`Modified from ...` を含む）を残し、変更点の一覧を更新する（Apache-2.0 §4(b)）。
- ビルドの出力は `minify: false`、`--target node`。`main.js` の import は host のモジュールだけ。
- 実機確認は macOS だけ。README と RECIPE に「Tested on macOS only」と書く。
- 各タスクの終わりに `bun run ci` が通る（Task 6 以前は、差分チェックの対象が古いルートの `mods/` なので、ビルドの出力をコミットに含める）。

## Review Focus

1. **オーバーレイを開いている間のフォーカス**: オーバーレイが `focused()` を奪うと、ファイルを開く先のタブや一覧の対象フォルダを取り違える。Task 1 の spike の結果に従い、Task 4 のテスト「開く先は、オーバーレイを開く前のタブ」で固定する。
2. **Git でないフォルダや巨大なフォルダ**: `git ls-files` が失敗するフォルダ、ファイルが数十万あるフォルダで、一覧が空のまま固まる、または全件を描いて固まる。Task 3 と Task 4 のテストで、`find` への切り替えと件数の上限（`LIST_LIMIT`）を固定する。
3. **key なしで開かれた editor**: エージェントが `pane.split {mod, props: {file}}` だけで開いた pane が、今は何もしない。Task 2 のテストで、開くこと、フォーカスで登録されること、そこにオーバーレイからファイルが届くことを固定する。
4. **editor を入れていない Files 連携**: クリックしても何も開かない状態は「してはいけないこと」に当たる。Task 5 のテストで、プレビューに戻ることを固定する。
5. **連続した操作**: オーバーレイで Enter を連打したり、Files を連続でクリックしたりしたときに、pane が重複して開く。今は Files のフォークにある待ち行列（`splitting` / `queuedOpens`）を、Task 1 で opener に移すときにテストごと移す。

### Task 3: 一覧の解析と絞り込み（純粋関数）

**Files:**
- Create: `src/core/quick-open/match.ts`
- Test: `tests/unit/quick-open.test.ts`

**Interfaces:**
- Produces:
  - `export const LIST_LIMIT = 20000;`、`export const SHOW_LIMIT = 50;`
  - `export function parseNul(stdout: string, limit: number): { paths: string[]; truncated: boolean }`（`git ls-files -z` の出力）
  - `export function parseLines(stdout: string, limit: number): { paths: string[]; truncated: boolean }`（`find` の出力。先頭の `./` を外す）
  - `export function rankPaths(paths: string[], query: string, limit: number): string[]`

- [ ] **Step 1: テストを書く**

```ts
test("parseNul drops the empty tail and stops at the limit", () => {
  expect(parseNul("a.ts\0b/c.ts\0", 10)).toEqual({ paths: ["a.ts", "b/c.ts"], truncated: false });
  expect(parseNul("a\0b\0c\0", 2)).toEqual({ paths: ["a", "b"], truncated: true });
});
test("parseLines strips ./ and blank lines", () => {
  expect(parseLines("./a.ts\n./b/c.ts\n\n", 10)).toEqual({ paths: ["a.ts", "b/c.ts"], truncated: false });
});
test("an empty query keeps the order and the limit", () => {
  expect(rankPaths(["b", "a", "c"], "", 2)).toEqual(["b", "a"]);
});
test("matches a subsequence, ignoring case", () => {
  expect(rankPaths(["src/main.rs", "README.md", "tests/main.rs"], "MainRS", 10)).toEqual(["src/main.rs", "tests/main.rs"]);
});
test("a contiguous match in the file name ranks first, then a subsequence in the file name, then in the path", () => {
  const paths = ["main/x.ts", "src/m_a_i_n.ts", "lib/main.ts"];
  expect(rankPaths(paths, "main", 10)).toEqual(["lib/main.ts", "src/m_a_i_n.ts", "main/x.ts"]);
});
test("ties go to the shorter path, then alphabetical", () => {
  expect(rankPaths(["b/a.ts", "a.ts", "c/a.ts"], "a.ts", 10)).toEqual(["a.ts", "b/a.ts", "c/a.ts"]);
});
```

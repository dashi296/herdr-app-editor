# Jump to Line and Text Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the editor open a file at a line and column. On top of that, add a popup that searches the focused folder for a literal string and opens the chosen hit at its line.

**Architecture:**
- Pure logic goes in `src/core/`:
  - `jump/jump.ts` turns a line, column and length into an editor range.
  - `search/search.ts` builds the `git grep` and `grep` arguments and parses their output.
  - `routing/routing.ts` gains a `jump` effect for a request that names the file already open.
- The editor view applies `at` after a load, or at once for the open file.
- `SearchView` reuses quick open's way of opening a file: an `open` command to an existing editor, or a detached `SPLIT_SCRIPT` call. Both now carry `at`.
- `SPLIT_SCRIPT` moves to `src/ui/split.ts` so both popups share it.

**Tech Stack:** TypeScript, Bun 1.3.5 (`bun test`, `bun build --target node`), gpui-kit / gpui-base / herdr host modules, oxlint, oxfmt, dependency-cruiser.

**Spec:** `docs/superpowers/specs/2026-11-20-search-design.md`

## Global Constraints

- Herdr Desktop 0.1.16. An overlay never creates a pane itself; new editor panes come from the detached `SPLIT_SCRIPT` (S10/S11).
- Read `props()` only in `init()`.
- All mod names live in `src/core/names.ts`. The new one is `MOD_SEARCH = "herdr-app-editor-search"`.
- `src/core/` imports no host modules (dependency-cruiser enforces this).
- `at` is `{ line: number; col?: number; len?: number }`.
  - `line` and `col` count from 1. `col` and `len` are in UTF-16 units of the editor's text.
  - `line` past the end clamps to the last line. `col` and `len` clamp to the line, not counting a trailing `\r`.
  - With no `col`, the cursor goes to the line start. With no `len`, the selection is empty.
- Search rules:
  - The match is literal (`-F`).
  - Smart case: `-i` only when the query has no uppercase letter.
  - At least 2 characters. Search starts 250 ms after typing stops.
  - At most 1 search runs at a time; only the newest query waits for it.
  - Timeout is 10 s. At most 500 hits are kept, and each shown line is cut at 200 characters.
- The search commands:
  - Git: `git grep -n -I --column --no-color --untracked -F [-i] -e <q>`.
  - Elsewhere: `grep -rnI -F [-i] --exclude-dir=.git --exclude-dir=node_modules -e <q> .`.
- `git grep --column` gives a 1-based byte column. Convert it to UTF-16 from the hit's line text.
- Status texts: "Type at least 2 characters.", "Searching…", "No matches.", "Cannot search this folder: <error>", "Showing the first 500 matches", "Stopped early: showing what was found", "No folder to search here.".
- A same-file `at` request jumps without a dialog and without reloading, and keeps unsaved edits. A pending save dialog for another file is closed and cancelled.
- `at` from split props is used only on a first load. When a saved pane state exists, it is ignored.
- `bun run ci` must pass. The build output (`editor/mods/*`) is committed.

## Review Focus

1. **`at` on a CRLF file.** Jumping to line 3 of `a\r\nb\r\nc` selects in `c`, and a `col` past the end stops before `\r`. Task 1 tests this.
2. **Hits containing astral characters (emoji) or multibyte text before the match.** The `git grep` byte column must become the right UTF-16 column. Task 4 tests this.
3. **A same-file `at` while that file is still loading** (a second pick right after a split). The last `at` must be applied after the load, not dropped. Task 3 tests this.
4. **Output cut mid-line by the 8 MiB cap or a timeout.** A half line must not become a hit with a wrong line number. Task 4 tests this.
5. **A query typed while a search is running.** Results of the old query must never be shown for the new query. Task 5 tests this.

Behaviour:
- `onCommand` reads `at` through `parseAt(m.at)`, puts it in the request, and passes `{ dirty, file: this.doc?.path ?? null, on: this.doc?.machine ?? null }`.
- A `jump` effect calls `jumpTo(at)`.

  - It also stores `pendingAt` when `this.doc` is set but the screen is not `ready`.
- `openFile(path, on, cx, at?)`.
  - It sets `pendingAt = at ?? null` at its start.
  - After `this.screen = { kind: "ready" }`, it calls `jumpTo(pendingAt)` if that is set, then clears it.

- `jumpTo(at)` computes `rangeAt(this.code.value(), at)`, then calls `set_selected_range` and `focus()` on the `EditorState`. With no `code`, it does nothing.
- In `init()`, `parseAt(p.at)` is read with the other props.
  - It is passed to `openFile` only when `target === initial`, that is, when no saved state was used.

### Task 4: Search arguments and output parsing (core)

**Files:**
- Create: `src/core/search/search.ts`
- Test: `tests/unit/search.test.ts`

**Interfaces:**
- Produces:
  - Constants:
    - `export const MIN_QUERY = 2, DEBOUNCE_MS = 250, HIT_LIMIT = 500, LINE_SHOW = 200;`
  - `Hit`:
    - `export interface Hit { path: string; line: number; col: number; len: number; text: string }`
    - `col` is the 1-based UTF-16 column in the full line, and `len` is the query's UTF-16 length.
    - `text` is the line with leading and trailing whitespace trimmed, cut to `LINE_SHOW`.
  - `export function ignoreCase(q: string): boolean`. True when `q === q.toLowerCase()`.
  - `export function gitGrepArgs(q: string): string[]`
  - `export function grepArgs(q: string): string[]`
  - `export interface Hits { hits: Hit[]; truncated: boolean }`
  - `export function parseGitGrep(stdout: string, q: string): Hits`. The format is `path:line:bytecol:text`.
  - `export function parseGrep(stdout: string, q: string): Hits`. The format is `./path:line:text`. The column is the first match of `q` in `text`, case-insensitive when `ignoreCase(q)`.
  - `export function byteToUtf16Col(line: string, byteCol: number): number`
  - Both parsers:
    - drop a final line without a trailing `\n` (output cut short);
    - drop lines that do not parse;
    - keep at most `HIT_LIMIT` hits and set `truncated` when there were more.

**Interfaces:**

It returns null on success, or the problem text to show (`NO_CLI` for exit 3, `Cannot open a new editor pane: <e>` when the spawn throws).
  - `SearchView`, with the same public shape as `OpenView` (`init`, `render`, `onKey`).

SearchView behaviour:
- **init** works like OpenView: it reads the overlay id, the location, the tab and the base pane. The input's placeholder is "Search in files…".
- **In a Git repository or not.**
  - It runs `git rev-parse --is-inside-work-tree` once at init in `cwd`.
  - Exit 0 means `git grep` is used; anything else means `grep`.
  - Its own `opts` are `{ cwd, on, timeout: LIST_TIMEOUT_MS }`.
- **On change:**
  - Under `MIN_QUERY` characters, it shows "Type at least 2 characters." and clears the hits.
  - Otherwise it records `wanted = q` and spawns a task: `await cx.sleep(DEBOUNCE_MS)`. If `wanted` is still `q`, it calls `run()`.
- **`run()`:**
  - If a search is running, it only sets `next = wanted` and returns.
  - Otherwise it sets `running = true` and execs with `SEARCH_TIMEOUT_MS = 10_000`.
- **When the search finishes:**
  - If its query is still `wanted`, the result is shown:
    - Exit 0 parses the output.
    - Exit 1 with empty stdout means "No matches.".
    - Any other exit with stdout parses the output and adds the notice "Stopped early: showing what was found".
    - Any other exit without stdout shows `Cannot search this folder: ${stderr || "exit " + code}`.
    - A rejected exec shows `Cannot search this folder: ${String(e)}`.
  - Then it clears `running` and, if `next` differs from the finished query, runs again.
- **Rows** show `path:line` (`t.dim`) and the hit text. Arrows, Enter and cmd/ctrl-Enter, Esc and click work as in OpenView.
- **choose(i, newPane):**
  - `at = { line, col, len }`.
  - If there is a target and no new pane is wanted, it calls `sendTo(target, file, on, at)` and dismisses.
  - Otherwise it calls `splitEditor({pane: base, direction: "right", mod: MOD_EDITOR, props: { key: id("e"), file, on, tab, before, at }}, MOD_SEARCH)`. On a problem it shows a notice and lets the person retry; otherwise it dismisses.

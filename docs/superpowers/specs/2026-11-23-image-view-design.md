# エディタペインで画像ファイルを表示する（#42）

作成日: 2026-11-23 / 状態: PR でレビュー中 / 関連: #42, #43, `docs/spikes/2026-11-23-s13-image.md`

## 目的

画像ファイルを開くと「looks like a binary file.」と出るだけだった。Files パネル、quick open、検索のどこから開いても、エディタペインに画像を表示する。

## 目標

- png / jpg / jpeg / gif / webp / bmp / tif / tiff を、ペインに収まる大きさで表示する。小さい画像は拡大しない。
- 再起動後、そのペインは同じ画像を開く。
- 同じ画像を開き直すと、ディスク上の今の内容が出る。

## 目標としないこと

- `.svg` の画像表示。これまで通りテキストとして編集する。
- 他のマシン上の画像。メッセージを出す。
- avif / heic。ホストが表示しない（S13）。これまで通り「binary」のメッセージ。
- エディタ mod がないときの Files パネル内プレビュー。上流フォークの差分が増えるので別にする。
- 拡大・縮小、パン、ディスク上の変更の自動反映。
- PDF（#43）。

## 方式

| 方式 | 得失 |
|---|---|
| アプリホーム配下に symlink を作り `image()` に渡す | コピーなし。ファイルの場所と大きさを問わない。`ln` がある macOS / Linux だけ。採用。 |
| `fs/promises` で読んでアプリホーム配下に書く | `exec` が要らず Windows でも動く見込み。ホーム配下のファイルしか読めず、開くたびに全体をコピーする。Windows だけで使う（未実行）。 |
| `image()` に絶対パスを渡す | 表示されない（S13）。 |

## 設計

- `core/media/media.ts`: `isImagePath(path)`。拡張子で決める。
- `ports/image-store.ts`: `expose(path, paneKey)` は `image()` に渡すパスを返す。呼ぶたびに新しいパスを返し、そのペインの古いものを消す。`release(paneKey)` は消すだけ。
- `adapters/herdr/image-store.ts`: `data/herdr-app-editor/images/<pane key>/<時刻>-<連番>` に symlink を作る。先に `test -f -a -r` で存在を確かめる（`ln -s` は相手がなくても成功する）。古いリンクは `rm -f` で名前を指定して消す。`expose` と `release` は1つずつ順に実行する（作成中のリンクが後から残らないように）。絶対パス以外は断る。消すのは、そのストアが作ったリンクと、名前の時刻が60秒より古いリンクだけ（ホストは1つのペインに mod のコピーを2つ起動して片方を捨てることがあり、捨てられた側が表示中のリンクを消さないように）。
- `ui/editor-view.ts`:
  - `load()` で、未保存の文書を離れる処理の後、`readTextFile` の前に分岐する。
  - 画面の種類に `image` を足す。文書（`doc` / `code`）は持たない。
  - ペインの状態（`panes/<key>`）にはテキストと同じ形で保存する。
  - 表示はヘッダー（ファイル名とパス）と、中央寄せの画像。
  - 表示直後の3秒間は 250 ms ごと、その後30秒までは1秒ごとに描き直す（S13: 読み込みが終わっても描き直されない）。
  - `close()` でリンクを消す。終了時に完了が見込めるのは新しく始めた `exec` だけなので（gpui-kit `View.close`）、自分が作ったリンクの `rm` をキューや fs より先に始め、下書きの書き出しより先に呼ぶ。フォルダは消さない（同じペインの mod のもう1つのコピーが、そこにリンクを作ろうとしていることがある）。

## 分かっている制約

- 画像を開いた後でテキストを開いたとき、リンクは次に画像を開くかペインを閉じるまで残る（数十バイト。Windows では画像のコピー）。
- 画像を表示しているペインは、クリックしても「最後にフォーカスしたエディタ」として登録されない（登録は `EditorState` の focus イベントとコマンドの受信時だけ）。メッセージ画面と空の画面も同じ。
- 画像のリンクを作っている最中にペインを閉じると、`close()` で始めた `rm` の後に `ln` が終わることがある。このため、閉じた後は `ln` を始めず、`ln` 実行中に閉じた場合は `close()` で `sh -c` も始め、1秒ごとに6秒間（`ln` のタイムアウト5秒より長く）消し直す。sh が終了時に止められた場合と、Windows でコピー中に終了した場合は残ることがある。
- 画像を表示したペインのキーごとに空のフォルダが残る。キーなしのペインは起動ごとにキーが変わるので、その分だけ増える。
- 開くたびに新しい名前を使うので、同じ画像の開き直しでもホストがパスごとに覚える画像が1件増える。メモリの増え方は測っていない。
- アプリの終了時に `rm` が間に合わなかった場合や異常終了した場合、キーなしで開いたペインのリンクは残る（次の起動では別のキーになる）。消す処理はない。キー付きのペインは、次にそのペインで画像を開いたときに60秒より古いリンクとして消える。
- 画像の読み込みに失敗しても（壊れたファイルなど）ホストは何も知らせないので、空のまま表示される。
- Windows の経路は実行していない（#38）。

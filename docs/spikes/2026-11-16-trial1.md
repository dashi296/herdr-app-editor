# 実機での動作確認 1回目（editor Mod / editor-files / editor レイアウト）

実施日: 2026-11-16 / 環境: macOS、Herdr Desktop 0.1.15 → 確認中に 0.1.16 へ更新 / 検証用フォルダ: `~/herdr-editor-trial`

## 手順と結果

| 手順 | 結果 |
|---|---|
| Files からファイルを開く | editor の pane が分割されて開いた |
| 編集 → ● の表示 → cmd-s → ● が消える | 期待どおり。`main.rs` がディスクに保存された |
| 編集したまま別のファイルを開く → Cancel／Don't save | 期待どおり。Don't save の後も `config.json` は変更されていない |
| CRLF のファイルで Enter → 保存 | `line1\r\nline2\r\nline3` になった（追加した行も CRLF）。S2b の対策が機能した |
| **2つ目以降のファイルを Files で開く** | **不具合**: Files が「Cannot list this folder」になり、ほかのファイルを選べなくなった |

## 不具合の原因と修正

Files はフォーカスのある pane の作業フォルダを表示する（上流の `location()`）。editor の pane には作業フォルダがないので、フォーカスが editor に移ると、Files は space のフォルダに切り替わってしまい、一覧を取得できなかった。

editor 側に問題はなかった。CLI から `editor.open:{json}` を直接送ると、既存の pane の中身が切り替わった。

修正（`src/entries/editor-files.js`）:

1. フォーカスが editor の pane にあるときは、同じ tab のターミナルの作業フォルダを表示する。
2. ユーザーから「2つのファイルを同時に編集できない」という指摘があった。そのため、**cmd-click（macOS 以外は ctrl-click）で新しい editor の pane に開く**ようにした。通常のクリックは、最後にフォーカスした editor で開く。

修正後の再確認では、(1) Files の一覧が維持される、(2) 通常のクリックで同じ pane の中身が切り替わる、(3) cmd-click で新しい pane に開いて2つのファイルを並べて編集できる、のすべてが期待どおりだった。

## あわせて直したもの

- 「Don't save」でファイルを切り替えたとき、または保存に成功したときに、保留中の下書きの書き込みを取り消してから下書きを削除するようにした（`DraftWriter.discard()`）。修正前は、取り消した編集の下書きが、遅れて書き込まれる可能性があった。
- 型定義を、0.1.16 が生成した `herdr.d.ts`・`gpui-kit.d.ts` に置き換えた。0.1.16 には master の API（`EditorState.focus()` / `selected_range()`、`checking()`、`watchFolder` の `cancel()`）が入っていた。

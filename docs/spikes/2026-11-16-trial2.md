# 実機での動作確認 2回目（外部変更・競合・下書き・R17・S8）

実施日: 2026-11-16 / 環境: macOS、Herdr Desktop 0.1.16 / 検証用フォルダ: `~/herdr-editor-trial`

| 確認内容 | 方法 | 結果 |
|---|---|---|
| R17: 読み取り専用ファイル（444） | `locked.txt` を CLI で split して開く | 「Read-only: you do not have permission to write this file.」の帯が出て、編集できない |
| clean な状態での外部変更 | シェルで README.md を書き換える | tab を表示すると3秒以内に自動で読み直した（非表示の間はポーリングしない設計どおり） |
| dirty な状態での外部変更 | ユーザーが入力した後、シェルで書き換える | 「The file changed on disk. Your edits are not saved.」の帯と「Reload／Keep mine」のボタンが出た。入力した内容は残った |
| Keep mine → cmd-s | ユーザー操作 | 「Save failed: the file changed on disk」の帯が出た。**ディスク上の外部変更は上書きされなかった**（受け入れ条件3） |
| pane を閉じた後の下書きの復元 | 保存せずに pane を閉じ、Files から開き直す | 「An unsaved draft … The file has changed since then.」の帯が出て、「Restore draft」で入力が戻った（G1） |
| S8: 入力遅延 | 50 KB / 400 KB / 1 MiB の .ts と、同じ内容の .txt | .ts は 50 KB でわずかに遅れ、400 KB で重く、1 MiB ではかなり重い。**.txt はどれもずっと軽い** → 主な原因はハイライト |

## S8 への対応

- 100 KB を超えるファイルは、ハイライトを切ってプレーンテキストで開く（`core/language` の `highlightFor`、`HIGHLIGHT_LIMIT = 100_000`）。
- ハイライトを切ったことは、帯「Syntax highlighting is off for files over 100 KB to keep typing fast.」で知らせる。
- 50〜100 KB では、わずかな遅れが残る。しきい値は、実際に使ったうえで見直す。

# スパイク結果: S2b（CRLF のファイルで Enter を押す）と Esc によるダイアログの返答

実施日: 2026-11-16 / 環境: macOS、Herdr Desktop 0.1.15 / スパイク: `spikes/s2b-esc/`、ログ: `docs/spikes/s2b-logs/result.json`

検証用の Mod を overlay で開き、ユーザーに手動で操作してもらった。終了後に Mod と `data/` を削除した。

## 結果

| 確認内容 | 結果 |
|---|---|
| S2b: CRLF の文書（`line1\r\nline2\r\n`）で Enter を押す | **`\n`（LF）が挿入された**。値は `line1\r\nline2\r\n\nx` になり、CRLF と LF が混在した |
| Esc: modal のダイアログを Esc で閉じる | **ダイアログの `close()` から返答が1回届いた**（`req` も一致） |

## 計画への影響

1. **CRLF のファイルは、保存の前に改行コードをそろえる**（`core/text`）
   - ファイルを開いたときに、改行コードを判定する。CRLF のみ／LF のみ／混在の3つに分ける。
   - **CRLF のみ**だったファイルは、保存の直前に、単独の `\n` を `\r\n` に変換する。Enter や貼り付けで入った LF だけが変換の対象になる。
   - **LF のみ**と**混在**のファイルは変換しない。混在のファイルは、元の状態を推測できないので、そのまま保存する。
   - 保存する本文と、ディスクとの比較に使う baseline の両方で、同じ変換後の文字列を使う。
   - P1 の「改行コードを不用意に変更しない」を満たすための処理として、unit test で網羅する。
2. **ダイアログの返答の経路**（`close()` に一本化）は、Esc・`closeOverlay`・`overlay.close` のすべてで確認できた。S5 の残りの項目はこれで解消した。

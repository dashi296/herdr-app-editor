# スパイク結果: S2（改行コードなどの保持）と S4（writeTextFile の挙動）

実施日: 2026-11-16 / 環境: macOS、Herdr Desktop 0.1.15 / スパイク: `spikes/s24-probe/`、ログ: `docs/spikes/s24-logs/result.json`

検証用の Mod を overlay で一度だけ開き、`~/herdr-spike-s24` と `/tmp/herdr-spike-s24-outside` の検証用ファイルだけを読み書きした。終了後に Mod・`data/`・検証用ファイルを削除した。tab と pane は変更していない。

## S2: EditorState と readTextFile

| 入力 | `EditorState.new({value}).value()` | `set_value` → `value()` |
|---|---|---|
| CRLF `a\r\nb\r\n` | 同一 | 同一 |
| BOM `﻿bom\n` | 同一 | 同一 |
| 末尾改行なし | 同一 | 同一 |
| タブ | 同一 | 同一 |
| 混在 `a\r\nb\nc\rd` | 同一 | 同一 |
| 単独の CR | 同一 | 同一 |
| 空文字列 | 同一 | 同一 |

`readTextFile` は、CRLF・BOM・末尾改行なしのいずれも、バイト列のとおりに返した（BOM は `﻿` として残る）。不正な UTF-8 は `stream did not contain valid UTF-8` で reject され、存在しないファイルは `null` を返した。

**結論**: 読み込みから EditorState を経由した保存までの経路では、改行コード・BOM・末尾改行は正規化されない。`core/text` で復元する処理は不要で、改行コードが混在するファイルを読み取り専用にする必要もない。

**未確認（S2b）**: CRLF のファイルで Enter を押したときに、`\n` と `\r\n` のどちらが挿入されるか。手動の入力が必要なので、Esc の確認とまとめて行う。

## S4: writeTextFile

| ケース | 結果 |
|---|---|
| expected が一致 | 成功。**パーミッション（640）は保たれる** |
| CRLF を含む本文 | バイト列のとおりに書かれる |
| expected が不一致 | `The file changed outside Herdr. Reload before saving; your draft is still here.` |
| **読み取り専用ファイル（444）** | **成功して上書きされる**（パーミッションは 444 のまま） |
| 読み取り専用ディレクトリ（555）内のファイル | `Permission denied (os error 13)` |
| 削除済みファイルに expected を付けて書く | 「changed outside Herdr」（再読込すると null なので、§2 の表で「削除」と表示できる） |
| 既存ファイルに expected=null で書く | 「changed outside Herdr」 |
| 新規ファイルに expected=null で書く | 作成される |
| symlink 経由 | リンクは保たれ、リンク先が更新される |
| **hard link** | **リンクが切れる**（書いた側は新しい inode になり、もう一方は古い内容のまま） |
| **xattr** | **独自の xattr（`com.example.s24`）は消える** |
| ちょうど 1 MiB | 成功 |
| 1 MiB + 1 byte | `Text file exceeds 1 MiB` |
| ホーム外（`/tmp`） | 成功 |
| 一時ファイル `.herdr-app-write-*` | 残らない |

## 計画への影響

1. **S2**: 改行コードなどの復元処理と、改行コードが混在するファイルを読み取り専用にする規則を、計画から外す。
2. **新しいリスク R17: 読み取り専用のファイルが上書きされる**
   - ディレクトリが書き込み可能だと、rename で置き換わってしまう。ユーザーが読み取り専用にしたファイルを編集・保存できてしまう。
   - mod API には stat がない。そのため保存の前に、ローカルでは `exec("test", ["-w", path])` で書き込み権限を確かめ、書けなければ保存を止めて理由を表示する。Windows の手段は S4 の Windows 版で確認する。
   - ファイルを開いたときにも同じ確認をし、書けないファイルは読み取り専用で表示する。
3. **hard link と xattr は保たれない**ことを確定事項として RECIPE に書く。所有者と ACL は未確認。
4. **エラー原文**が分かった。§2 の「保存失敗の扱い」は、再読込の結果で表示を決める方針のままでよい。原文は診断用に表示する。

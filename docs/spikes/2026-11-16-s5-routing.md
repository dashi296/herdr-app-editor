# スパイク結果: S5（ファイルを開く依頼の振り分け）と S3（保存キー）

実施日: 2026-11-16 / 環境: macOS、Herdr Desktop 0.1.15 / スパイク: `spikes/s5-routing/`、ログ: `docs/spikes/s5-logs/`

ユーザーが使用中のワークスペースに一時的な tab「s5-spike」を作って検証し、終了後に tab・Mod・`data/` を削除した。

## 結果

| # | 確認内容 | 結果 |
|---|---|---|
| 1 | `pane.focus` → `editor.open:{json}` を同じ処理の中で続けて送る | **届く**（2〜6ms、ack まで含む） |
| 2 | ペイロードに `.` と `:` を含む約20KBの JSON | **そのまま届く** |
| 3 | 宛先（`to`）が違う依頼 | 表示中の editor 全部に届き、宛先の照合で無視できる |
| 4 | 期限切れの依頼（`sentAt` が5秒前） | editor 側で無視でき、ack も返らない |
| 5 | Files の pane を zoom して editor を隠した状態で focus → open | editor は依頼を**受理した**（age 3ms）。しかし **ack が Files に届かなかった**。`pane.focus` で zoom が editor に移り、送り主の Files が非表示になったため（R6） |
| 6 | split した editor の `init` 時点の `focused().pane` | **自分ではなく、split 元の pane**（`focusedPane = 送り主`, `ownPane = null`）。split が終わった後は、新しい pane にフォーカスがある |
| 7 | split の前後で `panes()` を比べる | 新しい editor の pane ID を**確実に特定できた** |
| 8 | ダイアログの `close()` からの返答（開いた側の `closeOverlay(id)`／`overlay.close`） | **どちらも `close()` が呼ばれ、返答が1回届いた**（約1.5秒後、`first: true`） |
| 9 | Esc キーで閉じる | 未確認。手動確認のとき、editor のコピーが再起動していたため、ダイアログが開いていなかった |
| 10 | S3: Editor にフォーカスがある状態で cmd-s | **ルート要素の `on_key_down` に `cmd-s` が届いた**。Editor はこのキーを消費しない |
| 11 | S3: Editor の外側をクリックしてから cmd-s | 届かない。ルートの focus handle はクリックだけではフォーカスされない |
| 12 | `fs.writeFile` を順番に（await して）呼ぶ | **truncate される**（長い内容の後に短い内容を書くと、短い内容だけが残る） |
| 13 | `fs.writeFile` を await せずに並行して呼ぶ | **ファイルが壊れた**（JSON の後ろに古い内容が残った） |
| 14 | hot reload（S1-4） | 保存すると反映された。非表示のコピーは、次に表示されたときに `init` からやり直される |

## 計画への影響

1. **ack とタイムアウトによるフォールバックをやめる**（結果5）
   - ack の届き先である Files が、`pane.focus` の副作用（zoom の移動）で非表示になることがある。この場合、ack を待つ方式では editor が重複する。
   - 一方、結果1のとおり、`panes()` に存在する pane へ focus してから open を送れば、配送は FIFO で確定する。
   - → registry のエントリを `panes()` で検証できた場合は、focus と open を送るだけにする。ack は診断用のログにとどめる。
2. **editor の pane ID は Files が登録する**（結果6・7）
   - split した側が、前後の `panes()` を比べて新しい pane の ID を求め、registry に書く。
   - editor 自身は `"focus"` を受け取ったとき、またはクリックされたときに、補助として更新する。
3. **ストアへの書き込みは単一の writer に直列化することが必須**（結果12・13）。A/B 方式は、クラッシュに備えるために引き続き必要。
4. **保存キー**（結果10・11）
   - Editor にフォーカスがあるときの cmd-s は、ルートの `on_key_down` で受け取れる。
   - Editor の外側をクリックしたときは、ルートの handle にフォーカスを移す（`on_mouse_down` で `handle.focus()`）。
5. 非表示の間に hot reload されたコピーは、次に表示されたときに `init` からやり直す（結果14）。`init` で `focused()` に頼らない。

## スパイク中のインシデント

1回目の実行で、s5-files は `init` 時点の `focused().pane` を自分の pane とみなした（結果6と同じ問題）。実際には、ユーザーの別の tab にある Claude Code のターミナルの pane だった。そのため、検証用の editor がその tab に split された。

直後に `pane.close` で検証用の pane だけを閉じた。ターミナルには影響していない。2回目以降は、自分の pane を `panes()` で特定し、tab が一致しなければ中止するようにした。

- `shared.json` の `s5.registry` キーは残っている（削除する API がないため）。

# スパイク結果: Step 0（バージョン差）と S1（バンドル）

実施日: 2026-11-16 / 環境: macOS、Herdr Desktop 0.1.15（最新リリース）、Bun 1.3.5

## Step 0: 手元の 0.1.15 と調査に使った master `5216e6f` の差

計画は master `5216e6f` を調べて作成した。手元にある最新リリースの 0.1.15（`9950887`、2026-11-10）と比べると、計画が前提にしている次の API が **0.1.15 にはない**。比較は、アプリが書き出す `~/.config/herdr-app/herdr.d.ts`・`gpui-kit.d.ts` と、上流のタグ `v0.1.15` のソースで行った。

| API | 0.1.15 | 計画での用途 |
|---|---|---|
| `EditorState.selected_range` / `set_selected_range` / `replace` / `focus` | なし（`value` / `set_value` / `on` / `release` のみ） | §3 のキーボード移動（`state.focus()`）、R8 の selection の移し替え |
| `checking()` | なし | check 中の副作用の停止 |
| `watchFolder` の `cancel()`（`FolderWatch`） | なし（素の Promise を返す） | watch の解放 |
| `tab.new` / `space.new` の `focus` 引数 | なし | （計画では未使用） |

一方、§3 の振り分けの中核は 0.1.15 でも master と同じだった。

- `run_as` の `split_once(':')`、続く `split_once('.')`、`send_command` の処理（`v0.1.15:src/window.rs:2791-2810`、`src/mods.rs:668-680`）
- `src/mod_files.rs`（違いはテスト用の一時ディレクトリだけ）
- `openOverlay` の `modal`、`cx.timer.after`・`cx.sleep`、`mod.open`、`fs/promises` の関数一覧

**影響**: 0.1.15 を対象にする場合は、次の対応が必要になる。

- `state.focus()` が使えない。依頼を処理した後に、キーボードを editor に移せない。代わりの方法を S5 で探す。
- selection を移せないので、作り直したときはカーソル位置が先頭に戻る。
- check のガード（`checking()`）がない。後述の S1-3 のとおり、fs の呼び出しを try/catch で囲む必要がある。
- watch の解放（`cancel()`）がない。

## S1: バンドルと `herdr-app check`

スパイク: `spikes/s1-bundle/`（TS、ネストしたモジュール `./core/describe`、`fs/promises` を import）

### S1-1. ネストしたモジュールのバンドル → 成立

1ファイルにまとめた `main.js` で `herdr-app check` が通った。

### S1-2. Bun の `--target` → **`node` を使う**

| target | 結果 |
|---|---|
| `browser` | **`--external fs/promises` を指定しても、`var fs = (() => ({}))` という空のスタブに置き換わる。`herdr-app check` は通ってしまう**（`fs.readFile` が undefined になるだけで、エラーにならない） |
| `bun` | `import * as fs from "fs/promises"` は残る。ただし先頭に `// @bun` の pragma が付く |
| `node` | import がそのまま残り、余計な pragma も付かない。check も通る |

→ ビルドは `--target node --format esm` に固定する。check ではスタブ化を検出できないので、**計画どおり出力の検査（external の specifier が残っていること）が必須**になる。

### S1-3. check 中の fs 書き込み → **同期的に例外が出る**

`herdr-app check` に app home の外にある mod フォルダを渡すと、`fs.mkdir(appHome() + "/data/…")` が Promise を返さず、**同期的に例外を投げる**。メッセージは "is outside every granted write root"。`init()` から呼ぶと check が失敗する。

→ 0.1.15 には `checking()` がないので、fs の呼び出しはすべて、同期の例外と reject の両方を捕まえる形にする（`try { fs.x().catch(…) } catch {}`）。live のウィンドウで書き込めるかは S5 で確認する。

### S1-4. hot reload → 未確認

`~/.config/herdr-app/mods/` に置く必要があるので、S5 と一緒に確認する。
